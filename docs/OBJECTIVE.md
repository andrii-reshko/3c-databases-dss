# Розробка системи підтримки прийняття рішень

## 1. Мета завдання

Метою завдання є розробка програмної системи, яка забезпечує збереження та структуризацію даних, необхідних для прийняття рішень, а також формує основу для подальшої реалізації аналітичного блоку СППР.

## 2. Постановка задачі

Необхідно розробити базову версію системи підтримки прийняття рішень, яка працює з:
• множиною альтернатив;
• множиною критеріїв;
• оцінками альтернатив за заданими критеріями.

На цьому етапі система не виконує обчислення рішень, а лише забезпечує збереження та організацію даних.

## 3. Основні сутності системи

У системі повинні бути реалізовані такі сутності:

#### Альтернатива (Alternative)
- ідентифікатор (id);
- назва (name);
- опис (description).

#### Критерій (Criterion)
- ідентифікатор (id);  
- назва (name);  
- тип (maximize або minimize);  
- опис (description).  

#### Оцінка (Evaluation)
- ідентифікатор альтернативи (alternative_id);
- ідентифікатор критерію (criterion_id);
- значення оцінки (value).

## 4. Функціональні вимоги

Розроблена система повинна забезпечувати можливість:
• додавання, редагування та перегляду альтернатив;
• додавання, редагування та перегляду критеріїв;
• задання типу критерію (maximize або minimize);
• введення оцінок альтернатив за критеріями;
• перегляду матриці оцінювання альтернатив.

## 5. Збереження даних

Для реалізації системи необхідно використати одну з баз даних:
• реляційну (SQL); або
• документно-орієнтовану (MongoDB).

Структура даних повинна відповідати визначеним сутностям.

### 6. Вимога щодо розширюваності системи

У системі необхідно передбачити окремий компонент (модуль або сервіс), який у подальшому буде відповідати за аналітичну обробку даних та прийняття рішень.

Цей компонент у майбутньому має забезпечувати:
• обчислення оцінок альтернатив;
• врахування ваг критеріїв;
• ранжування альтернатив;
• формування рекомендацій.

На даному етапі:
• аналітичний компонент не потрібно реалізовувати;
• однак він повинен бути передбачений в архітектурі системи (у вигляді інтерфейсу, окремого класу, сервісу або заглушки).

## 7. Результати виконання
У звіті надати:
1. програмну реалізацію системи;
2. опис архітектури (1–2 сторінки);
3. схему бази даних (ER-діаграму або аналог);
4. приклад заповнених даних:  
   • не менше 3 альтернатив;  
   • не менше 3 критеріїв;  
   • заповнену матрицю оцінювання.
